## О проекте

**typecode** - terminal-based тренажёр слепой печати для программистов.

Цель проекта - создать инструмент, который обучает не просто быстрой печати, а быстрому набору именно программного кода: синтаксиса языков, специальных символов, типичных конструкций.

Приложение должно ощущаться как настоящая Linux-утилита - минималистичный TUI в стиле `btop`, `lazygit`, `htop`.

**Цели разработки:**
- Глубоко изучить язык C
- Создать сильный open-source проект для портфолио
- Сделать реально полезный инструмент для программистов

**GitHub:** https://github.com/ginluv21/typecode
**GitHub Project (задачи):** https://github.com/users/ginluv21/projects/3

## Архитектура

Проект построен на модульной архитектуре. Каждый модуль - отдельная пара `.c` / `.h` файлов с чёткой зоной ответственности.

```
main.c
  │
  ├── ui.c      ← инициализация ncurses, цветовые пары
  ├── menu.c    ← главное меню, навигация
  └── lesson.c  ← загрузка урока, ввод, метрики, результаты, выбор из папки
```

**Принцип взаимодействия:**
- `main.c` вызывает `ui_init()`, крутит цикл `menu_run()` -> `lesson_select_menu()`
- `lesson_select_menu()` вызывает `lesson_run()` для каждого выбранного урока
- Модули не должны напрямую вызывать друг друга кроме случаев выше

## Модули

### main.c
Точка входа. Регистрирует обработчик `SIGWINCH`, инициализирует ncurses через `ui_init()`, крутит главный цикл меню до выбора Exit.

**Ключевые функции:**
- `main()` - точка входа, цикл меню
- `handle_sigwinch()` - обработчик SIGWINCH, ставит флаг resize

---

### ui.c / ui.h
Инициализация и завершение ncurses. Регистрирует цветовые пары.

**Ключевые функции:**
- `ui_init()` - `initscr`, `cbreak`, `noecho`, `keypad`, 6 цветовых пар
- `ui_cleanup()` - `endwin()`

**Цветовые константы (`include/typecode.h`):**
```c
#define COLOR_GREEN_ON_BLACK  1  // правильный символ
#define COLOR_RED_ON_BLACK    2  // ошибка
#define COLOR_YELLOW_ON_BLACK 3  // курсор
#define COLOR_WHITE_ON_BLACK  4  // обычный текст
#define COLOR_CYAN_ON_BLACK   5  // элементы UI
#define COLOR_BLUE_ON_BLACK   6
```

---

### menu.c / menu.h
Отрисовка и цикл главного меню с ASCII-логотипом.

**Ключевые функции:**
- `draw_main_menu(int selected)` - рамка, лого, пункты меню
- `menu_run()` - цикл ввода, возвращает `MenuOption`

---

### lesson.c / lesson.h
Весь урочный стек: загрузка файла, отрисовка текста, цикл ввода, метрики, экран результатов, выбор урока из папки.

**Ключевые структуры:**
```c
typedef struct {
    char *text;
    int   len;
    char  name[LESSON_NAME_MAX];
} Lesson;

typedef struct {
    int correct, errors, wpm;
    float accuracy;
    int duration_sec;
    struct timespec start;
    int started;
} Metrics;

typedef enum { CHAR_UNTYPED=0, CHAR_CORRECT, CHAR_WRONG } CharState;
typedef enum { RESULT_LESSONS=0, RESULT_REPEAT, RESULT_MAIN_MENU } ResultAction;
```

**Ключевые функции:**
- `lesson_load(path)` - читает .txt файл, имя из имени файла без расширения
- `lesson_free(lesson)` - освобождает память
- `lesson_draw(...)` - рисует заголовок, текст с цветами по CharState, строку метрик
- `lesson_run(path)` - основной цикл: ввод, метрики, повтор по R
- `lesson_show_results(...)` - итоговый экран WPM/Accuracy/Errors/Time, ждёт R/Esc/Q
- `lesson_select_menu(dir)` - сканирует dir на .txt, сортирует, показывает список

**Формула WPM:**
```
WPM = (correct / 5) / время_в_минутах
```

**Обработка спецсимволов:**
- `\t` - отрисовывается как `>` с продвижением до следующего кратного 4 столбца
- `\n` - автоматически пропускается (CHAR_CORRECT), курсор на него не встаёт

## Формат файлов уроков

Обычный текстовый файл `.txt`. Каждый файл - один урок. Файл содержит текст для набора.

**Пример** (`lessons/latin/01_home_row.txt`):
```
asdf jkl; asdf jkl; fjfj dkdk slsl aaaa
fj fj dk dk sl sl aa ss dd ff jj kk ll
```

**Пример** (`lessons/c/for_loop.txt`):
```
for (int i = 0; i < n; i++) {
    printf("%d\n", arr[i]);
}
```

**Правила именования файлов:**
- Латиница, нижнее подчёркивание, без пробелов
- Числовой префикс для сортировки: `01_`, `02_`, ...
- Расширение `.txt`

## Соглашения по коду

### Именование
- Функции: `module_action()` → `stats_save()`, `typing_start()`
- Структуры: PascalCase → `TypingState`, `SessionResult`
- Константы: UPPER_SNAKE → `COLOR_PAIR_CORRECT`, `MAX_LESSONS`
- Переменные: snake_case → `best_wpm`, `lesson_path`

### Файлы
- Каждый модуль - пара `.c` / `.h`
- В `.h` только объявления, никакой реализации
- Include guard в каждом `.h`:
```c
#ifndef MODULE_H
#define MODULE_H
// ...
#endif
```

### Память
- Каждый `malloc` должен иметь соответствующий `free`
- Функции, возвращающие указатели, документируют кто отвечает за `free`
- Проверять возвращаемое значение `malloc` на NULL

### Комментарии
- Комментировать только неочевидные места
- Не комментировать то, что понятно из названия функции

### Стиль
- Отступы: 4 пробела
- Открывающая скобка на той же строке: `if (x) {`
- Максимальная длина строки: 100 символов

## Git workflow

### Ветки
- `main` - стабильная версия
- `feature/название` - новая фича
- `fix/название` - исправление бага

### Коммиты
Формат сообщения:
```
тип: краткое описание (до 72 символов)

Подробное описание если нужно.
```

Типы: `feat`, `fix`, `refactor`, `docs`, `style`, `test`

Примеры:
```
feat: add typing engine with real-time metrics
fix: correct WPM calculation on fast input
docs: update README with installation steps
```

### Pull Requests
- Каждая задача из issues - отдельный PR
- PR должен закрывать issue: `Closes #7` в описании
- Код ревью минимум одного участника перед мержем

## Сборка и запуск

### Зависимости

```bash
# Ubuntu / Debian
sudo apt install gcc libncurses-dev make

# Arch
sudo pacman -S gcc ncurses make

# Fedora
sudo dnf install gcc ncurses-devel make
```

### Команды

```bash
make          # сборка
make run      # сборка и запуск
make debug    # сборка с AddressSanitizer
make clean    # очистка артефактов
```

### Отладка

```bash
make debug
./typecode

# Или через valgrind:
valgrind --leak-check=full ./typecode
```
